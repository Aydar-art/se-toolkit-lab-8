1. Описание проекта (для LLM)

Название: RPG To-Do Telegram Bot (Demo Version)

Цель: Создать Telegram-бота, который превращает реальные задачи в RPG-игру с PvP-дуэлями. Бот должен работать асинхронно, хранить данные в SQLite, поддерживать регистрацию, добавление/выполнение задач, профиль игрока и пошаговые бои между пользователями (с ручным вводом ОД, без автоматических inline-кнопок в демо-версии).

Технологии: Python 3.9+, aiogram 3.x, aiosqlite, asyncio.

Функциональные требования (MVP):

Регистрация игроков через /start (сохранение в БД).
Добавление задачи с ручным указанием ОД (1–8) через пошаговый диалог (FSM).
Просмотр списка задач /tasks.
Выполнение задачи /complete — начисление XP, повышение уровня, увеличение HP, накопление ОД за день.
Профиль /profile (уровень, XP, HP, ОД сегодня).
PvP-дуэль /fight @username — вызов, принятие/отказ, пошаговый бой с текстовыми командами (без inline-кнопок, пользователи вводят атака, защита, пропустить). Учёт ОД, HP, определение победителя, начисление бонусного XP.
Ежедневный сброс ОД в 00:00 UTC через фоновую задачу.
База данных SQLite с таблицами players и tasks.
Не требуется в демо-версии: навыки, inline-кнопки для боя, LLM-оценка сложности, рейтинги.

## 5. Готовый план реализации (который LLM напишет по системному промту)

Вот как будет выглядеть план, который LLM сгенерирует сама (пример). Вы можете использовать его как чек-лист.

### План реализации (Demo Version)

1. **Структура проекта и база данных**
   - Создать папки и файлы.
   - Написать `config.py`, `.env`.
   - Реализовать `database.py` с таблицами `players`, `tasks`.
   - Инициализация БД в `bot.py`.

2. **Регистрация и профиль**
   - Хендлер `/start` с вызовом `register_player`.
   - Хендлер `/profile` с выводом статистики из БД.
   - Хендлер `/help` со списком команд.

3. **Управление задачами (FSM)**
   - Класс состояний `AddTaskStates`.
   - Хендлер `/add_task` → запрос названия.
   - Хендлер для названия → запрос ОД.
   - Хендлер для ОД → сохранение задачи в БД.
   - Хендлер `/tasks` → вывод списка задач.
   - Хендлер `/complete` → выполнение задачи (начисление XP, уровня, HP, ОД).

4. **PvP-дуэли (базовые)**
   - Хендлер `/fight @username` → поиск соперника, проверка ОД, отправка запроса.
   - Принятие/отказ через текстовые команды (например, `/accept`).
   - Логика боя: поочерёдный ввод `атака`, `защита`, `пропустить` в личных сообщениях с ботом.
   - Учёт ОД и HP, завершение боя, начисление бонусного XP.

5. **Ежедневный сброс ОД**
   - Фоновая задача `daily_reset()` с проверкой времени.
   - Запуск вместе с поллингом в `bot.py`.

6. **Финальное тестирование и отчёт**
   - Запуск бота, проверка всех команд.
   - Написание инструкции по запуску.
   - Создание `requirements.txt`.

## 6. Как использовать этот материал

1. **Скопируйте** раздел 1 («Описание проекта») и раздел 2 («Системный промт») в новый диалог с любой LLM (ChatGPT, Claude, DeepSeek, локальная модель).
2. **Дождитесь**, пока LLM напишет план (как в разделе 5).
3. **Отправляйте** промт «Реализуй шаг 1» и далее по одному шагу.
4. **Проверяйте** отчёты LLM. Если код содержит ошибки, попросите «Проверь код шага X и исправь».
5. **В конце** получите полностью работающего бота.

Если вы хотите, чтобы я сам (как LLM) прямо сейчас начал реализацию по этому плану, просто напишите **«Начинай шаг 1»** — и я буду последовательно писать код, отчитываться и ждать вашего подтверждения.
